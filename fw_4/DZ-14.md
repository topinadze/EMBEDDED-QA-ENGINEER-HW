# ДЗ-14: Тестування Wi-Fi та BLE

**Що треба мати:** ESP32-S3 DevKit, дві прошивки з цієї папки (`git1` - по одному файлу, або `git3` - покомпонентно), Python 3.10+, pytest, pyserial, bleak, смартфон з додатком **nRF Connect**.

**Формат здачі:** ZIP-архів `DZ-14_<Прізвище>.zip` з папкою `dz14/`.

**Оцінка:** 20 балів - дві прошивки, кожна частина по 10 балів.

Опис прошивок і вимоги до них - у `PRD.md` поруч із цим файлом. Тестуємо проти PRD.

---

## Підготовка

**Важливо: це дві незалежні прошивки, а не одна.** На платі одночасно живе тільки одна з них. Порядок роботи такий:

1. Прошити `station_WiFi` → повністю виконати Частину A (всі Wi-Fi тести) → зафіксувати результати у REPORT.md.
2. Тільки після завершення Частини A: зробити `erase-flash`, прошити `Bluedroid_GATT_Server` → виконати Частину B.

Перемикатись туди-сюди між частинами не потрібно і не варто - закінчили одну, тоді беретесь за іншу. Частини незалежні: жоден тест Частини A не потребує BLE-прошивки, і навпаки.

Інструкції з прошивання - у README відповідних папок (`git1` - одним файлом, `git3` - покомпонентно). Перед **кожною** прошивкою обов'язково `erase-flash` - інакше у NVS можуть лишитись дані попередньої прошивки.

### Тестова Wi-Fi мережа

Для Частини A потрібна мережа, якою ви керуєте (знаєте пароль, можете її вимкнути). Варіанти:

- **Хотспот з телефона (рекомендовано)** - увімкніть точку доступу на смартфоні. Обов'язково: діапазон **2.4 GHz** (ESP32 не бачить 5 GHz; на iPhone - увімкнути "Maximize Compatibility", на Android - вибрати 2.4 GHz у налаштуваннях точки доступу). Пароль задайте самі - він же буде "валідними креденшилами" у тестах.
- **Домашній роутер** - якщо мережа двохдіапазонна з одним SSID, переконайтесь що 2.4 GHz увімкнено.

SSID і пароль у тести не хардкодьте - винесіть у конфіг (env-змінні або окремий `config.py`/`.env`, який не здаєте в архіві - у REPORT.md вкажіть, як його заповнити).

### Інструмент для BLE

- **nRF Connect for Mobile** (Android / iOS) - рекомендовано, найзручніший варіант: скан, підключення, browse сервісів, підписка на notifications/indications, write у характеристики.
- Альтернативи на ноутбуці, якщо телефона немає: **LightBlue** або **Bluetility** (macOS), **Bluetooth LE Explorer** (Windows, Microsoft Store). Увага: nRF Connect for Desktop для BLE потребує окремий Nordic-донгл - без нього не підійде.

## Частина A: Wi-Fi - автоматизоване тестування

Тестуємо прошивку `station_WiFi` через UART (pyserial + ваш DeviceDriver + pytest).

### A1. Розширення драйвера

Додайте у свій `DeviceDriver` методи:

- `wifi_scan()` - повертає список мереж (хоча б імена SSID)
- `wifi_connect(ssid, password)` - проходить інтерактивний діалог команди `connect`: дочекатись промпта SSID, відправити, дочекатись промпта пароля, відправити, дочекатись результату. Повертає True/False
- `wifi_status()` - повертає dict: підключено чи ні, SSID, IP, RSSI
- `wifi_disconnect()`

Жодних `time.sleep()` для очікування промптів - тільки очікування по патернах.

### A2. Позитивні тести

`tests/wifi/test_wifi_positive.py`:

- `test_scan_finds_networks` - scan повертає непорожній список, ваша тестова мережа присутня
- `test_connect_success` - підключення з валідними креденшилами; `status` після цього показує SSID та IP (IP матчиться на `\d+\.\d+\.\d+\.\d+`)
- `test_disconnect` - після disconnect `status` показує відключений стан
- `test_credentials_survive_reboot` - підключитись, ребутнутись, викликати `connect` з порожнім вводом (Enter) - пристрій підключається по збережених креденшилах (PRD FR-W4)

### A3. Негативні тести

`tests/wifi/test_wifi_negative.py`:

- `test_wrong_password` - валідний SSID + неправильний пароль (>= 8 символів): підключення не відбувається, у виводі є повідомлення про фейл
- `test_short_password` - пароль < 8 символів: відхиляється одразу з `password too short`, спроби підключення немає
- `test_nonexistent_ssid` - неіснуючий SSID: фейл або таймаут, пристрій живий після цього (відповідає на `help`)

## Частина B: BLE - ручне тестування + 1 автотест

Тестуємо прошивку `Bluedroid_GATT_Server` (SENTRY-BLE) переважно вручну через nRF Connect. Паралельно тримайте відкритий термінал з UART-логом (115200) - кожна дія по BLE має підтвердження у лозі, і це ваш другий канал спостереження.

### B1. Ручні перевірки (чек-лист)

Кожен пункт - у REPORT.md: що робили, що очікували (посилання на FR з PRD), що отримали, **доказ** (скріншот nRF Connect, фрагмент UART-логу, для LED/реле - фото або опис фізичної реакції).

1. **Scan** - у nRF Connect знайти пристрій `SENTRY-BLE`, зафіксувати RSSI.
2. **Connect + discovery** - підключитись; переконатись, що є сервіси `0x180D` (Heart Rate) і `0x1815` (Automation IO), а в `0x1815` - дві характеристики (LED і RELAY, UUID у PRD). У UART-лозі - `Connected, ... remote <MAC>`.
3. **Heart Rate** - підписатись на індикації `0x2A37`: значення оновлюються щосекунди, діапазон 60-80 bpm.
4. **HR spike** - у UART-терміналі команда `hr spike` (або кнопка K1): у nRF Connect наступні значення ~190. Скрін з аномальним значенням.
5. **LED через BLE** - write `01` у LED-характеристику: фізичний LED загорівся, у лозі `LED ON!`. Write `00` - згас, `LED OFF!`.
6. **RELAY через BLE** - write `01`/`00` у RELAY-характеристику: клацання реле, у лозі `RELAY ON!`/`RELAY OFF!`.
7. **Read після write** - після write `01` read характеристики повертає `01` (і так само для `00`).
8. **Конфлікт каналів керування** - write `01` у LED по BLE, потім вимкнути LED іншим каналом (кнопка K2 або UART-команда `led off`), потім read по BLE: має повернутись `00` (PRD FR-G5).
9. **Reconnect** - розірвати з'єднання (з nRF Connect або UART-командою `disconnect`): у лозі `Disconnected`, пристрій знову видно у скані, повторне підключення працює.

Якщо якийсь пункт поводиться не за PRD - це баг: оформіть міні баг-репорт у REPORT.md (кроки, очікуване, фактичне, доказ).

### B2. Один автотест на bleak

`tests/ble/test_ble_smoke.py` - один тест `test_ble_led_dual_channel`:

1. BleakScanner знаходить `SENTRY-BLE`
2. Підключитись, write `0x01` у LED-характеристику
3. По UART (pyserial) переконатись, що у лозі з'явилось `LED ON!`
4. Write `0x00`, переконатись у `LED OFF!`
5. Відключитись

Це смок "залізо + радіо + два канали спостереження працюють разом". bleak асинхронний - використовуйте `pytest-asyncio` або обгорніть в `asyncio.run()`.

## Обов'язкові вимоги

- Структура проєкту як у ДЗ-08: `drivers/`, `tests/`, `conftest.py`, `pytest.ini`, `requirements.txt`
