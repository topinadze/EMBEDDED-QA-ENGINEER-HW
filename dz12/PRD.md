# Product Requirements Document (PRD) — HomeTherm v2

## 1. Загальний опис продукту
**HomeTherm v2** — це кліматичний контролер (розумний термостат) на базі плати **SENTRY-C1 (ESP32-S3)**. Пристрій призначений для автоматичного керування опалювальним обладнанням (через реле), зчитування даних із сенсорів, локальної індикації стану та взаємодії з користувачем.

> **Обґрунтування HIL-архітектури:** Для забезпечення детермінованості, апаратної безпеки та високої швидкості проходження E2E-тестів у HIL-стенді та Wokwi-моделі застосовано **емуляцію фізичної величини (Sensor Emulation)**. Ультразвуковий датчик **US-100 (GPIO5/18)** зчитує відстань у см, яка розглядається алгоритмом як еквівалент температури в °C ($20\text{ см} \equiv 20^\circ\text{C}$). Це дозволяє проводити перевірку спрацьовування реле за мілісекунди без використання нагрівальних елементів.

## 2. Технічний стек
* **Мікроконтролер (DUT):** SENTRY-C1 (ESP32-S3).
* **Периферія:**
  * Дисплей OLED SSD1306 (I2C: GPIO1 SDA / GPIO2 SCL).
  * Датчик відстані / емулятор температури US-100 (GPIO5 Trig / GPIO18 Echo).
  * Опалювальне реле (GPIO8, Active HIGH).
  * Матрична клавіатура 1x4 (GPIO38–41, Internal Pull-Up).
  * Світлодіоди індикації: Yellow RUN (GPIO4), Green PASS/HEAT (GPIO6), Red FAIL/ERROR (GPIO7).
* **Діагностика та логування:** Hardware UART (GPIO43 TX / GPIO44 RX, 115200 8N1) через USB-UART CP2102.
* **Контроль живлення:** LCUS-2 USB-Relay (CH340) для апаратного розриву лінії 5V VBUS.
* **Тестове середовище:** Python 3.11+, PyTest, PySerial.

## 3. Перелік вимог

### Функціональні вимоги (FR)
* **FR-1 (Heating Relay Control):** Перемикати стан опалювального реле на GPIO8 у стан HIGH, якщо зчитане значення еквіваленту температури (відстані з US-100) менше за заданий поріг ($20\text{ см} / 20^\circ\text{C}$), та у LOW, якщо значення дорівнює або перевищує поріг.
* **FR-2 (OLED Display Output):** Виводити графічний інтерфейс та оновлювати поточну телеметрію (показники сенсора та статус реле) на екрані OLED SSD1306 через шину I2C (GPIO1/GPIO2).
* **FR-3 (Matrix Keyboard Input):** Опрацьовувати натискання кнопок KEY1–KEY4 (GPIO38–41) для ручного коригування цільового порогу температури.
* **FR-4 (Status LED Indication):** Забезпечити світлодіодну сигналізацію: Жовтий LED (GPIO4) — живлення/готовність, Зелений LED (GPIO6) — режим обігріву (HEAT ON / PASS), Червоний LED (GPIO7) — помилка сенсора (FAIL).

### Нефункціональні вимоги (NFR)
* **NFR-1 (Cycle Stability):** Забезпечити безперервну та стабільну роботу системи без аварійних перезавантажень (Watchdog / Kernel Panic) протягом випробувального циклу тривалістю 180 секунд.
* **NFR-2 (US-100 Sensor Handling):** Коректно обробляти відсутність відгуку від датчика US-100 (таймаут $> 30\text{ ms}$), переводити реле у безпечний вимкнений стан та вмикати Червоний LED (GPIO7).
* **NFR-3 (Power Restoration Time):** Час повного відновлення функціонування системи та виходу в робочий режим після апаратного знеструмлення через USB-реле має становити менше 10 секунд.

## 4. Критичні сценарії використання
1. **Аварійне знеструмлення (Power Cut & Recovery):** Апаратне розмикання 5V лінії живлення та автоматична перевірка часу відновлення системи (NFR-3).
2. **Обробка обриву/помилки сенсора:** Виключення сенсора з ланцюга, перевірка переходу у безпечний стан (Relay OFF, FAIL LED ON) (NFR-2).
3. **Локальна зміна порогу:** Зміна уставного значення з кнопок KEY1/KEY2 та перевірка реакції реле (FR-1, FR-3).
